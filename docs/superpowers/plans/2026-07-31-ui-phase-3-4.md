# UI Plan B (Phases 3–4): Two-way Telegram, Rendered Charts, Deferred Items

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two-way Telegram (commands, pinned live message, photo alerts), service-rendered annotated charts, and the four deferred items: broker-side SL-hit events, equity-curve trade markers, P/L in trade history, and the strategy/basket sync hook. Specs: `docs/superpowers/specs/2026-07-31-ui-design.md` §3 (Telegram, renders) and the deferred list in the Plan A ledger; `2026-07-31-boll-stochrsi-strategy-design.md` Known Limitations (sync hook).

**Architecture:** Telegram gains a transport class + background asyncio tasks in the FastAPI lifespan (long-poll `getUpdates` for commands; 60 s pinned-message editor) — started only when token+chat are configured, so tests and token-less runs are unaffected. Charts rendered with matplotlib (Agg) from candles cached off `/analyze`. EA: `OnTradeTransaction` catches broker-side SL closes; `CStrategy` gains no-op sync hooks (`OnBasketClosed`, `OnEntryRejected`) that `BollStochRsi` overrides.

**Tech Stack:** Python (adds `matplotlib` to `service/requirements.txt`); MQL5 (compile deferred); vanilla JS.

## Global Constraints

- Python tests from `service/`: `.venv/bin/python -m pytest`; suite green after every task. Telegram tests use a fake transport — no real network.
- Background tasks must not start when `TELEGRAM_BOT_TOKEN` or `TELEGRAM_CHAT_ID` is empty (the test default). All Telegram failures are swallowed (fail-open); they can never affect `/analyze`, `/heartbeat`, or trading.
- The switch command path reuses `app.state.pending_switch` exactly as the dashboard does (at-least-once, cleared on heartbeat confirmation, cancellable with empty id).
- MQL5 tasks: recorded self-checks; compile deferred to the final manual checklist. UI/telemetry failures never touch order flow.
- Reason string for broker SL closes: exactly `"stop-loss"`. Trade-event `profit` field: realized basket profit for `close` events, `0.0` otherwise.
- Commits: repo style + trailer `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.

### Task 1: Telegram transport + command handlers

**Files:**
- Modify: `service/app/telegram.py`, `service/app/main.py`
- Test: `service/tests/test_telegram_commands.py` (new)

**Interfaces:**
- Produces (telegram.py): class `TelegramClient(token, chat_id, transport=None)` — `transport` is a callable `(method: str, payload: dict, files: dict|None) -> dict|None` defaulting to an httpx-based implementation POSTing `https://api.telegram.org/bot<token>/<method>` (json when `files is None`, multipart otherwise; 10 s timeout; returns parsed json or None on any error). Methods: `send_message(text) -> dict|None`, `send_photo(caption, png_bytes) -> dict|None`, `edit_message(message_id, text) -> dict|None`, `pin_message(message_id) -> bool`, `get_updates(offset) -> list` (long-poll `timeout=25`).
- Produces (telegram.py): `handle_command(text: str, app) -> str | None` — pure function mapping a command to a reply string using `app.state` (`latest_heartbeat`, `pending_switch`, `db`):
  - `/status` → equity, balance, floating P/L, open positions count/detail, kill-switch state, active strategy (+ pending arrow), window/exposure — from the latest heartbeat; "no heartbeat yet" when None.
  - `/stats` → per-strategy lines from `db.stats()["by_strategy"]`: id, signals, resolved, hit %, avg move.
  - `/history` → last 10 rows of `db.recent_trades(10)`: time, event, strategy, direction, lots@price, reason, profit if present.
  - `/switch <id>` → sets `app.state.pending_switch = id`, replies "switch to <id> queued — confirms on next EA heartbeat"; bare `/switch` → replies with current pending + "use /switch <id>, /switch cancel"; `/switch cancel` → clears, replies "pending switch cleared".
  - Unknown command → None (no reply).
- Produces (main.py): `async def telegram_poller(app)` — loop: `get_updates(offset)`, for each update with a `message.text` starting with `/` and `message.chat.id == chat_id`, call `handle_command`, `send_message` the reply if not None; advance offset; `await asyncio.sleep(1)` between polls; every exception → `await asyncio.sleep(5)` and continue. Started in lifespan via `asyncio.create_task` ONLY when token and chat_id are both set; task cancelled on shutdown.
- Existing `send_alert`/`format_report` stay (used by `/analyze`); they may delegate to `TelegramClient` internally but their signatures must not change.

- [ ] **Step 1: Failing tests** — `test_telegram_commands.py`: build a `TelegramClient` with a recording fake transport (list of `(method, payload)`), assert `send_message`/`send_photo`/`edit_message` hit the right methods with the right payload keys; `handle_command` tests using a stub app object (`types.SimpleNamespace`) with `latest_heartbeat=None` → "/status" mentions no heartbeat; with a populated heartbeat → reply contains equity and active strategy; "/switch boll_stochrsi_v1" sets `pending_switch` and the reply names it; "/switch cancel" clears it; "/stats" includes a by_strategy id; unknown "/foo" → None. Plus: lifespan does NOT create the poller task when token empty (TestClient run → `app.state.telegram_task is None`).
- [ ] **Step 2: Verify failure. Step 3: Implement. Step 4: Full suite green. Step 5: Commit** — `feat(service): two-way telegram — transport, commands, poller`.
