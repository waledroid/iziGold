# UI: Hybrid Telegram + Local Web Dashboard — Design Spec

**Date:** 2026-07-31
**Status:** Approved in conversation; pending user review of this document
**Builds on:** [2026-07-29-xau-assistant-design.md](2026-07-29-xau-assistant-design.md),
[2026-07-30-strategy-framework-design.md](2026-07-30-strategy-framework-design.md)

## 1. Goal

Visibility into the running system from two surfaces, each doing what it is
good at: **Telegram** for push alerts, quick checks, and remote commands
from the phone; a **local web dashboard** for live monitoring, equity
curve, trade history with screenshots, and the strategy head-to-head
comparison built on the per-strategy `stats()` scorecard.

Decisions fixed during brainstorming: hybrid (not Telegram-only, not
web-only); EA heartbeat every 5 s; both real MT5 chart screenshots and
service-rendered charts; content = live trades, trade history with
entry/exit/reason, MoneyWatch status, AI accuracy stats, equity curve,
signal log, strategy comparison.

## 2. EA additions (all fail-open)

1. **Heartbeat** — `EventSetTimer(5)`; every 5 s POST `/heartbeat`:
   equity, balance, floating P/L, open positions (ticket, direction, lots,
   open price, SL, profit), kill-switch state, equity high-water mark,
   exposure minutes used today, trading-window state, spread, active
   strategy id. Failure = no-op; never touches trading logic.
2. **Remote strategy switch** — the heartbeat response is normally `{}`;
   when a switch was queued (Telegram `/switch <id>` or web button) it is
   `{"switch_to": "<id>"}`, returned on every heartbeat **until the EA's
   heartbeat reports that id as active**, then cleared (at-least-once
   delivery; applying an already-active id is a no-op). The EA validates
   the id against the registry, applies the switch **at the next bar
   boundary** (never mid-bar), and logs it. Unknown id → ignored
   with a log line. Only compiled-in strategies are selectable; every
   safety rail (kill switch, live-account guard, MoneyWatch) is untouched.
3. **Trade events + screenshots** — on every open/add/close POST
   `/trade-event`: `{event, strategy_id, direction, lots, price, sl,
   reason, ticket}`; reason strings: `"signal BUY"`, `"signal SELL"`,
   `"pyramid add"`, `"stop-loss"`, `"profit target"`, `"reversal"`,
   `"kill switch"`, `"strategy EXIT"`. On open and close (not adds), call
   `ChartScreenShot()` and upload the PNG bytes as the request body of
   `POST /screenshot?event=<event_id>`.

## 3. Service additions

**Endpoints:**
- `POST /heartbeat` → store + return `{}`, or `{"switch_to": id}` while a
  switch is pending (cleared when a heartbeat reports it active).
- `POST /trade-event` → insert into `trades`.
- `POST /screenshot?event=<id>` → raw PNG body saved to
  `service/screenshots/<event_id>.png`, path recorded on the trade row;
  retention cap keeps the most recent ~500 files.
- `GET /ui` → dashboard HTML. `GET /ui/state`, `/ui/trades`, `/ui/stats`,
  `/ui/equity` → JSON the page polls. Localhost use only; no auth.

**Storage (same SQLite):**
- `heartbeats` — persisted at most once per ~60 s (5 s stream held in
  memory for the live view): ts, equity, balance, floating_pl, open_count,
  kill_switch, exposure_min, active_strategy.
- `trades` — ts, event, strategy_id, direction, lots, price, sl, reason,
  ticket, screenshot_path, render_path.
- `signals` — unchanged; comparison view reads `stats()["by_strategy"]`.

**Telegram (two-way):** background task long-polls `getUpdates` (no
webhook / public IP). Commands: `/status` (live basket + MoneyWatch),
`/stats` (per-strategy scorecard), `/history` (last N trades with
reasons), `/switch <id>` (queues the switch; confirms when the EA
acknowledges). Entry/exit alerts attach the EA screenshot as a photo. One
**pinned live-status message** is edited every ~60 s (within Telegram edit
rate limits): equity, open basket, distance to kill switch.

**Service-rendered charts:** on trade close, render an annotated candle
chart (entry/exit arrows, stop, AI forecast band at entry) from candles
the service already receives. matplotlib (Agg, headless) — one new
dependency. Sent alongside the EA screenshot in Telegram; shown in web
history next to it.

## 4. Web dashboard

One self-contained HTML file at `GET /ui` — no build tooling, plain JS
polling the JSON endpoints every 5 s. Top to bottom:

1. **Live strip** — equity, floating P/L, open positions with per-position
   profit, active strategy, kill-switch distance, window/exposure state.
   Red banner when the heartbeat is stale (> 30 s: "EA not reporting").
2. **Equity curve** — canvas chart from `/ui/equity` (1-minute heartbeat
   rows) with trade markers.
3. **Strategy comparison** — head-to-head table from `by_strategy`:
   signals, resolved, hit-rate, avg move, live-vs-shadow badge, and a
   "switch to this" button (same queued-command path as `/switch`).
4. **Trade history** — reason, P/L, thumbnails (EA screenshot + service
   render, click to enlarge).
5. **Signal log** — recent signals incl. shadows with AI
   verdict/confidence/regime.

## 5. Safety invariants

- Every UI feature is read-only toward trading except the switch command,
  which selects among compiled-in strategies only, applies at bar
  boundaries, and is logged + confirmed.
- Heartbeat/Telegram/screenshot failures never block or delay trading
  (fail-open, same rule as the AI).
- No UI path can re-enable a tripped kill switch — that reset stays
  manual in MT5 by design.

## 6. Testing

- pytest: heartbeat store/round-trip; switch-queue one-shot semantics
  (delivered once, cleared on EA confirmation); trade-event + screenshot
  storage and retention cap; equity downsampling; `/ui/*` JSON contracts
  matching the fields the page's JS reads.
- Telegram command handlers tested against a faked HTTP layer.
- EA side: manual MT5 checklist (compile, heartbeat visible in service
  log, screenshot lands on disk, `/switch` round trip confirms).

## 7. Phasing (each shippable alone)

1. Heartbeat + live state + equity curve + dashboard skeleton.
2. Trade events + screenshots + history view.
3. Telegram two-way: commands, pinned message, photo alerts, remote switch.
4. Service-rendered charts + comparison-view polish.

## 8. Out of scope

- Public/remote hosting of the dashboard, auth (localhost only).
- Kill-switch reset from any UI.
- Per-shadow basket simulation (unchanged from framework spec).
